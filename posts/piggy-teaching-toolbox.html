AI 教学视频多模态素材生成平台

做一节课的素材很碎：写脚本、找图、配音、做字幕，每步换一个工具，中间结果还接不上。 这个工具把这条链路收进一个六步向导。先说清楚它产出什么—— 图片、音频、字幕和提示词这些原材料，不是视频文件； 运镜提示词以文本导出，拿去剪辑工具或图生视频工具里用。

六步向导与数据流

输入主题、受众与知识点，模型展开为分镜（含中英文旁白、图片提示词、运镜提示词和时长）， 随后生成场景图、配音、字幕，最后归集打包。步骤条按项目状态解锁到对应进度， 页面刷新或重进后进行中的任务会被自动接回。一次完整生成的数据流：

  • 创建项目 → 分镜脚本（LLM）→ 场景图（带角色参考图）→ 上传 COS
  • → 中英文配音 → 拼接整段音频 → 上传 COS
  • → 导出时在 COS 内归集到 exports/{id}/ → SCF 云函数打 ZIP → 302 下载

分镜生成有两种模式：一次生成和逐镜生成，配合选择的时长决定镜数。 逐镜那条路每次带上前后文，叙事不会到第五镜突然变成另一个故事。 风格内置教学、儿歌、读绘本/故事、朗诵四种预设，再加一个可写描述的自定义风格。

角色一致性

场景图生成时最多携带 3 张角色参考图，让同一角色在不同场景里外观稳定。 角色库内置 20 个模板，分动物、植物、食物、物品、奇幻五类，也可以让模型出角色创意。 单镜支持重绘，不影响其他分镜。

分镜内容、提示词与资源状态都有人工编辑入口。生成质量再稳定也要人收尾， 所以整个流程按「可以停下来改」来设计，而不是一键出片。

结构化输出

模型输出统一走 JSON，解析端做容错、时长归一和角色 ID 过滤，再过 Pydantic 参数校验。 角色 ID 过滤这一步很值：模型会在旁白里写出根本不存在的角色名， 挡在生成之前比事后重做整段配音便宜得多。

配音与字幕

每个分镜生成中英文两条音频，全部完成后拼成整段，镜间插 0.3 秒静音。 字幕按真实音频时长生成 SRT，单镜和整段各一份——不按估计时长凑， 否则配音和字幕会越走越偏。分镜里可以选 17 种情感（分三类）。

这条目前没接上 情感、强度、语速、音量在界面上能改、也正确存进了数据库， 但发给语音合成的值是固定的，所以现在听不出差别。这是我记在 README 已知限制里的第一条。

任务与状态

项目、分镜、角色与资源状态落在 MySQL，产物地址也落库，所以已经生成完的分镜不会因为重启而丢。 分镜、重绘、配音、导出都走任务队列，前端轮询进度，配环形进度和带时间戳的生成日志。

队列本身是进程内的字典：进程重启任务就没了，多 worker 也不共享，重启后要重新发起 （前端会提示是服务器重启导致的）。只有分镜和配音任务参与重复提交去重， 导出和单图重绘不在里面。所有生成步骤串行执行，没有并发——单节课的量够用， 以后要提速改的就是这一层。

测试

后端 22 个测试文件、293 个测试函数，其中 16 个文件带属性测试（55 个 @given、51 个自定义策略）。测试不需要真实数据库也不需要 AI Key： 数据库用内存 SQLite，AI 调用全部打桩。所以改解析和状态逻辑时本地一条 pytest 就能验，不产生调用费用。

有 3 个测试文件当前收集不了（它们 import 了已经删掉的模块），跑全量会报错， README 里写明了跳过方式。前端没有自动化测试，类型检查靠构建时的 vue-tsc；仓库也没有 CI。

其他已知边界

  • 场景图生成失败不会中断任务，最后仍标记为 images_ready，要自己看每个分镜的状态。
  • 英文配音失败会被吞掉，整段拼接失败只记日志。
  • 没配语音服务的 Key 时不报错，而是静默生成静音 WAV。
  • 删除项目不清理 COS 上的文件，生成用的临时目录也不清理。
  • 有几处配置项是空壳（模型名在代码里写死），还有一段写好但没接进调用链的重试逻辑。

安全上还有没收拾完的账（口令哈希、CORS 范围、部分接口的归属校验）， 所以这个工具只在本地和局域网里跑，没有暴露到公网。
