军考方向的 AI Agent 学习平台

一个备考场景的 Agent 平台：问答、搜题、知识卡片、备考规划、主观题批改共用一套会话与记忆。 我负责 Agent 编排、分层记忆、RAG 检索与评测、批改链路，以及把原来挂在 PHP 上的 AI 能力 迁到 Python 服务。代码在公司仓库里，这里只写我做的事和拿到的数。

要解决的麻烦

备考这几件事本来是分开的：搜题一个入口、问答一个入口、批改又一个入口。 用户在一次学习里连着问，模型每轮都要重新搞清楚「你是谁、刚才在做什么、已经用了哪个能力」。 另外老服务是 PHP 的，AI 相关的逻辑越接越重，流式输出和长任务都不好写。

所以这个平台的目标不是「接一个大模型」，而是把多种能力收进同一个会话上下文里，并且跑得稳。

Agent 编排

对外是一个统一的 EduAgent。开放式学习问答由模型自己判断该激活哪个能力； 业务侧明确指定时直接装载对应 Skill，不给模型选择的机会。目前挂了五类能力： 题目解析、知识卡片、备考规划、智能搜题、主观题批改。

  • 多轮会话与「已经激活了哪些能力」由 Checkpointer 保存，重启会话后状态能接上。
  • 能力按 Skill 装载而不是一次全塞进 Prompt，上下文长度和路由干扰都小一些。
  • 路由结果单独评测，避免「看起来答得不错」掩盖选错能力的问题。

三层记忆

上下文分成三层：会话状态、长期记忆、用户画像。MySQL 存记忆的事实源， 偏好、事实、批改结果由 Taskiq 异步抽取，再做摘要和向量化。

层放什么怎么用
会话状态本轮与近几轮的上下文、已激活能力Checkpointer 直接恢复
长期记忆偏好、事实、历史批改结论语义召回 + 关键词检索合并去重后注入
用户画像薄弱点、进度这类聚合结论按用户隔离注入 Prompt

记忆本身要能被改：支持修正、软删除，访问热度也会更新， 不然一次写错的偏好会一直挂在每次对话里。

RAG 与离线评测

检索侧是 Milvus 向量库 + LightRAG + Neo4j 图数据。评测做成 JSONL 的离线链路， 指标用 Recall 与 F1@1/3/5/10，回答质量再加一路 LLM Judge，避免只看召回不看内容。

  • 约 300 条标注集调优之后，Recall@5 在 86%–89%，检索 P95 0.6–0.8 秒。
  • 约 500 条意图样本上，能力路由准确率 92%–94%。
  • 评测集和指标口径固定下来之后，改 Prompt 才知道是变好还是变坏。

主观题批改

批改是一条长链路：题目与答案校验 → 多图内容提取 → 评分依据检索 → 采分点拆解 → 结构化评分 → 报告持久化。难点集中在视觉模型那一段，手写答案常常是多张图， 图片地址还可能失效。

  • 给视觉模型加了 URL 并发校验，30/45 秒两档超时，失败走备用模型重试。
  • 证据不足时输出一个可解释的异常状态，而不是硬给一个分数。
  • 评分结果按采分点结构化落库，报告页能看出分是怎么来的。

长任务怎么不丢

批改、知识入库、RAG 评测、记忆写入都是长任务。用 Dishka 统一 API、gRPC 和 Worker 三边的依赖与资源生命周期，任务侧由 AnyIO + Taskiq 承载。

  • 有进度追踪、取消和失败重试；进程宕机后任务能被恢复继续跑。
  • 再用 MySQL 与 Redis 定时对账，兜住队列和状态不一致的情况。

迁移与压测

把 PHP 侧的 AI 能力迁到 Python 服务，gRPC 流式接口重构了一版， 补上共享密钥鉴权、限流、Deadline 和健康检查。在 Docker 4C8G、20 并发、 约 2000 次完整请求的口径下：

指标结果
吞吐7–9 QPS
成功率99%+
首 Token P951.8–2.4 秒
完整链路P95 5–7 秒 / P99 8–10 秒
