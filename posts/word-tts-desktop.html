小猪 wordTTS 桌面配音工作台

老师手上的原始素材往往是 Word 或 Excel：一张词汇表、一段对话练习。要变成音频， 就得复制粘贴到某个在线合成页、逐条点生成、再手动改名对齐顺序。 这个桌面应用把这段重复劳动收起来——导入文档、核对内容、配置声音、生成、试听与下载， 五段流程走完拿到成品。

解析文档，而不是解析文本框

应用直接读取 .docx 与 .xlsx，包括其中的词汇题目结构， 并按文档里的标记自动分配声部：

  • w / W → 英语 Amanda 女声
  • m / M → 英语 George 男声
  • 无标识内容默认 Amanda，保证不会静默漏条目

语速、语调、音量都支持 0–100 的任意整数值，输出统一为 MP3，质量选项对应码率， 常用参数可以存成预设。

交付校验

TTS 服务返回成功不等于文件可用。这里只把 服务端确认 READY + verified、且格式元数据与预期一致 的音频放进交付集合；支持逐条试听、单文件保存和 ZIP 打包保存。

为什么卡这么严 批量生成最常见的事故是「200 条里有 3 条是空文件或采样率不对」， 而人是在课堂上打开压缩包时才发现。校验前置到交付环节，宁可少给也不能给错。

长任务的可恢复性

一次生成可能持续几分钟，中间涉及外部服务、进度回调和文件落盘。界面上给的是 结构化时间线而不是转圈进度条：哪一条在排队、哪一条失败、失败原因是什么。 同时支持断线恢复、取消与失败重试。

本机历史中心保留最近 20 个任务，可以重新查看、试听、下载或归档。 归档保留审计事实与产物文件，归档不等于物理删除—— 这是刻意选的语义，避免用户以为点了一下就没了。

桌面分发工程

桌面端是 Electron 承载 Python 后端，macOS 与 Windows 安装包都由 GitHub Actions 自动构建。应用内自带版本中心：启动后检查 GitHub Releases，支持可选与强制更新、 下载、重启安装和更新日志展示。

平台做法
macOS.dmg，打开即用或拖入 Applications 的原生流程
Windows独立 HTML 自绘 Setup.exe，安装/更新/卸载共用一套界面
更新优先 .blockmap 差分下载，条件不满足自动回退全量

Windows 安装器先出界面、再按需解压 payload，避免长时间白屏；支持无边框窗口拖动、 选择安装目录与安装范围、数据保留策略、完成后可靠启动应用，以及桌面/开始菜单快捷方式清理。

可测试性

正式包默认走真实讯飞调用，但 --smoke-test 始终只跑逻辑离线流程、 不打开真实页面；直接诊断后端时可用 --disable-real-provider 或环境变量显式离线。这样 CI 里能验证流程，又不产生调用费用。

渲染层只保留工作台单一入口，workflow 数据与任务记录由服务端目录独立持久化， 界面更新不会创建第二套 Shell。
